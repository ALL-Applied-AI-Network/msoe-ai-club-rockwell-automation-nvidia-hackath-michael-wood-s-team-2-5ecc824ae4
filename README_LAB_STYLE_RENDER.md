# ProcessDNA — Isaac Sim video with CV Lab Capture UI

This folder contains an adapter for the Digital Twin workstream. It reproduces the **existing lab-capture preview appearance**:

- Top black state bar with color-coded `moving` / `pouring` / `settled, measured`, etc. (`SIM` replaces `REC` to distinguish synthetic footage).
- Yellow/green/blue vial inspection rectangle, depending on state.
- Original right-side dark history panel from `lab_capture.py`, with vial count, color swatches, recipe labels when supplied, and provisional dE00 comparisons and flags **only when generated by the existing `LiveVialReader`**.
- Same `SignalTracker`, `LiveVialReader`, and `detect_vial_color` package as the real CV branch, with *synthetic* FillCam frames as input.
- Full-HD 1920x1080 output that preserves the original 640:480+330:480 panel aspect ratio, using letterboxing rather than distorting the image.

No pre-rendered video is needed for the final simulation loop. The script uses Isaac Sim `rep.AnnotatorRegistry.get_annotator('rgb')`, runs CV inside the capture loop, and writes lossless PNGs + a MJPEG AVI draft and structured history data. Use PNGs for high-quality H264 encoding.

## GB10: preflight UI / detector on one saved frame (no Isaac Sim startup)

```bash
cd ~/csi_digital_twin_v1
python3 -m py_compile tools/render_cv_lab_style.py tools/lab_capture_ui.py
~/isaacsim/python.sh tools/render_cv_lab_style.py \
  --cv-root ~/MAIC_CV \
  --offline-frame outputs/clean_final_frames/frame_0350.png \
  --roi 290 290 35 55 \
  --out-dir outputs/lab_style_offline_test
```

Expected outputs: `lab_style_preview.png`, `offline_cv_result.json` and console quality/ROI source. **The panel shows zero vials for a still image: a single image cannot establish a temporal fill event.** `--roi` is manual region measurement, not automatic vial detection.

## GB10: short real Isaac Sim render + live tracker test

```bash
~/isaacsim/python.sh tools/render_cv_lab_style.py \
  --cv-root ~/MAIC_CV \
  --start 300 --end 330 \
  --fps 30 --subframes 4 \
  --render-width 1280 --render-height 960 \
  --roi 290 290 35 55 \
  --out-dir outputs/lab_style_live_test
```

Check `outputs/lab_style_live_test/frames.jsonl`, `vials_live.jsonl`, and `ProcessDNA_LabStyle_Preview.avi`. The state tracker is still configured from the `FillCam` JSON. If that config was copied unmodified from `vial_fill`, **motion event detection can be wrong or fail**. Check frame states and vial history before making claims. The fixed ROI affects only *measurement*, not automatic event tracking.

## GB10: final render (after preflight)

```bash
nohup ~/isaacsim/python.sh tools/render_cv_lab_style.py \
  --cv-root ~/MAIC_CV \
  --start 1 --end 686 \
  --fps 30 --subframes 8 \
  --render-width 1280 --render-height 960 \
  --roi 290 290 35 55 \
  --save-camera-frames \
  --out-dir outputs/ProcessDNA_Final_LabStyle \
  > outputs/lab_style_render.log 2>&1 < /dev/null &
disown
```

Use `--fps 60` for **true 60fps sampling** (about 1371 samples if the USD timecode rate is 30), with a fresh output directory. On the first pass, 30fps is lower risk and closer to the original USD animation.

If automatic FillCam location becomes calibrated, omit `--roi`. Never present manually specified coordinates as automatic detection.

If you have a **verified synthetic** vial-by-vial recipe plan, add `--run-plan path.csv`. Without it, the original `LiveVialReader` intentionally leaves recipes and flags absent. You cannot assume there are 8 vials in the animation simply because the real lab demo saw 8.

## Convert lossless PNGs to a presentation MP4 (Windows PowerShell with FFmpeg installed)

Download `presentation_frames` (can be large) and run:

```powershell
ffmpeg -framerate 30 -start_number 0 -i "frame_%05d.png" -c:v libx264 -preset slow -crf 16 -pix_fmt yuv420p -movflags +faststart ProcessDNA_LabStyle_Final.mp4
```

Use `-framerate 60` if the original render was 60fps. Don't interpolate or change playback rate needlessly. The AVI can also be converted if transferring PNGs is inconvenient, but PNGs produce the best source for H.264.

## Important evidence boundaries

- Real `LiveVialReader` state, vial count, recipe labels and flags are not faked; the right panel may remain empty if FillCam calibration is wrong or the prerecorded USD animation has no detectable full fill/settle cycles.
- The FillCam config cloned from the lab camera is not calibrated just because its JSON schema loads. Fix region positions and signal thresholds before interpreting event results.
- The current CSI USD visual liquid shader is not physical mixing or calibrated contamination ground truth. Outputs are synthetic, not verified factory defect labels.
- Rendering script depends on the actual CV branch package. It was syntax-checked and the composition tested locally against a user-provided FillCam image; it has **not** yet been executed on the GB10 within this chat.
